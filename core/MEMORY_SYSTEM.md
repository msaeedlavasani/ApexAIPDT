# Memory System

## Purpose

Memory prevents APDT from repeatedly rediscovering the same project facts, decisions, patterns, and corrections.

## Memory layers

### Stable memory
Long-lived rules and architecture that change infrequently.

Examples:
- product principles;
- technology constraints;
- design tokens;
- architecture boundaries.

### Operational memory
Current project state.

Examples:
- active initiatives;
- known blockers;
- current migration status.

### Episodic memory
Important events and completed decisions.

Examples:
- why a component was rejected;
- incident findings;
- major trade-offs.

### Learned memory
Patterns discovered from repeated evidence.

Examples:
- recurring agent mistakes;
- repeated manual corrections;
- emerging reusable patterns.

## Promotion rule

Do not store every conversation. Promote information into durable memory when it is likely to affect future decisions.

## Memory hygiene

Memory must have:

- owner/source;
- status;
- date or version when relevant;
- confidence where uncertainty exists.

Obsolete memory should be superseded or removed rather than accumulated indefinitely.

## Learning loop

OBSERVATION → PATTERN → VALIDATION → PROMOTION → RULE/REGISTRY/WORKFLOW UPDATE

A single anecdote should not automatically become a global rule.
