# Project Initialization Workflow

## Goal
Transform an approved product idea into an initialized project-specific AI development team.

## Phase 1 — Product discovery

Capture:

- problem;
- target users;
- value proposition;
- business model assumptions;
- success metrics;
- known requirements;
- unknowns;
- constraints.

Output: Product Brief.

## Phase 2 — Project characterization

Determine:

- product type;
- domain complexity;
- UX complexity;
- technical complexity;
- realtime needs;
- data sensitivity;
- operational risk;
- asset/content complexity.

Output: Project Profile.

## Phase 3 — Team assembly

Select the smallest capable set of brains and create a Team Manifest.

Output: Team Manifest.

## Phase 4 — Constitution

Generate project-specific:

- product principles;
- design rules;
- technology constraints;
- source-of-truth priority;
- protected decisions;
- autonomy policy;
- definition of done.

Output: Project Constitution.

## Phase 5 — Context system

Create:

- project context map;
- repository map;
- component registry where applicable;
- asset registry where applicable;
- initial architecture map.

Output: Context package.

## Phase 6 — Validation strategy

Define the test pyramid, quality gates, observability, and release criteria appropriate to the project.

## Phase 7 — Ready state

A project is initialized when:

- team roles are defined;
- authority boundaries are defined;
- source-of-truth hierarchy exists;
- context routing exists;
- memory locations exist;
- workflows exist;
- validation gates exist;
- human decision boundaries are explicit.

The system may then enter development.
